# Agent notes

## Web UI (`web/src`)

The UI is one React app shared by the PWA and the VS Code webview. All interactive chrome comes from ui-sdk (`@ui-sdk/react`): menus, menubar, toolbars, splitters (`Resizable`), trees, tabs, dialogs, selects, toasts, the command palette. Do not hand-roll these.

- Follow the ui-sdk skill (`.agents/skills/ui-sdk/SKILL.md`) and read `web/node_modules/@ui-sdk/react/docs/llms.txt` before changing UI code.
- Before adding a component, search `web/node_modules/@ui-sdk/react/docs/core.md` for an existing part, and read `web/node_modules/@ui-sdk/react/docs/rendering.md` for how parts render and take props.

### Styling (Tailwind CSS v4)

Style with Tailwind utilities in `className`. Tailwind runs through `@tailwindcss/vite`; there is no `tailwind.config`.

- `styles/index.css` is the entry. Its first three lines fix the cascade order: `@layer ui-sdk;`, `@import "tailwindcss";`, and `@import "@ui-sdk/core/web.css" layer(components);`. Utilities beat ui-sdk's styles, so a class on a part overrides it without `!`. The file also holds `@theme`, the custom variants and a few global element rules.
- `styles/tokens.css` defines the colour tokens as CSS variables for light, `[data-theme=dark]` and the VS Code webview, and maps them onto ui-sdk's `--ui-*` tokens. `@theme inline` exposes them as utilities: `bg-chrome`, `text-muted`, `border-border2`, `bg-acc`, `text-t-k`. Use these. Never write a raw hex or a Tailwind palette colour such as `bg-gray-100`; the default palette is removed.
- The theme scales are replaced, not extended:
  - text: `text-3xs` 10px to `text-5xl` 32px, with `text-ui` 12.5px and `text-base` 13px; font size only, line height is inherited
  - radius: `rounded-xs` 3px, `rounded-sm` 4px, `rounded-md` 6px
  - `ease-snap` and `shadow-pop`
  - for line height, use `leading-[19px]` or `leading-[normal]`, never `leading-normal` (which is 1.5)
- Custom variants:
  - `dark:` for `[data-theme=dark]`
  - viewport widths: `narrow:` ≤1180px, `compact:` ≤900px, `phone:` ≤720px. `phone` must stay in sync with `PHONE_QUERY` in `state/store.ts`.
  - Default breakpoints (`md:` and so on) are removed.
- Show state with data and ARIA variants on ui-sdk's own attributes: `data-highlighted:`, `data-checked:`, `aria-pressed:`, `aria-expanded:`. Avoid conditional class strings for these.
- `styles/plain.css` is the only plain CSS. It is unlayered because CodeMirror injects its theme unlayered at runtime, and it holds CodeMirror's internal DOM (`.cm-host .cm-*`), the PC-line decoration and the reduced-motion reset. Add to it only what a utility can't reach.
- Repeated class strings become a constant or a small component, so there is one style per thing:
  - `components/ui/`: `Button` (the one button style, `variant="solid"` for the primary action), `Input`, `Check`, `select`, `menu`, `tree`, `resizable`, plus `kit.tsx` (`Row`, `Empty`, `Note`, `Kv`, `CAPS`, `INSET`)
  - `panel/Out.tsx`
  - `editor/marks.ts`, `editor/tabs.ts`
  - `cx()` in `lib/cx.ts` joins classes. There is no tailwind-merge, so don't pass a class that fights one the wrapper already sets.
- ui-sdk finds some parts by component type (a tree branch finds its `TreeGroup` this way). Re-export those parts unwrapped and style them from the parent, as `ui/tree.tsx` does for `TreeGroup`.
- Popups render inside their trigger's DOM. A ui-sdk rule written for the menubar or toolbar can therefore reach menu items; set the item's size on the item itself (see `MenuSubTrigger`).
- Format touched files with `npx prettier --single-quote --print-width 160 --object-wrap collapse <files>`. The repo has no Prettier config, so check the diff and don't reformat files you didn't change.
- CodeMirror 6 is the editor (`components/editor/cm.ts`); the logic analyzer draws on a canvas.
- Routes are TanStack Router file routes in `web/src/routes` with hash history. `routeTree.gen.ts` is generated by the Vite build; don't edit it.

## Hosts

- `web/src/host/client.ts` talks to an `IdeBridge`: the PWA bridge (`host/web/`) runs the WebAssembly core, and the VS Code bridge posts to the extension.
- Keep to the JSON-RPC methods `cli/src/wasm_api.rs` and `cli/src/server.rs` already serve. A new method the UI calls must be added to `UI_RPC_METHODS` in `web/src/host/protocol.ts`, or the extension rejects it.
- The extension (`extension/src/webviewPanel.ts`) checks every path the webview sends against the workspace folders and the open project. Keep new host actions behind that check.

## Checks

- `cd web && npm run build` (strict TS, app and service worker) and `cd extension && npm run build` must pass.
